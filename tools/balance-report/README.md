# Mass and balance reports

`occt-balance-report` reads an existing parametric model and an explicit component
selection. It reports per-component mass, per-material totals, assembly center
of gravity and central inertia, plus CG distance and percentage along a reference
chord. It preserves the input model. Densities must be assigned in the model or
supplied explicitly; the command has no assumed default material.

```sh
OCCT_BRIDGE_LIB_DIR="$PWD/build/bench" \
  cargo build --release --manifest-path rust/occt-parametric/Cargo.toml \
  --bin occt-balance-report
LD_LIBRARY_PATH="$PWD/build/bench" \
  rust/occt-parametric/target/release/occt-balance-report \
  wing.model.json tools/balance-report/wing-example.json /tmp/wing-balance.json
```

The output file must be new. Measurements and validation finish before exclusive
file creation; existing files are never overwritten. Invalid inputs or geometry
failures leave no report. A disk error during writing can leave a partial file.
Exit 0 means the report was written; exit 1 means an input or execution error.
The report is data only, with no recommended CG range or flight-stability verdict.

## Selecting components and materials

```json
{
  "schema": "occb-balance-report-v1",
  "materials": [
    { "id": "measured", "name": "Measured effective density", "density_kg_per_cubic_meter": 1000 }
  ],
  "components": [
    { "id": "selected_body", "source": "prototype", "output": "body", "material": "measured" }
  ],
  "reference": { "kind": "wing_project", "project": "layout.json" }
}
```

Each `source` names an existing instance and `output` selects one final solid
feature. Each selection gets a distinct, new `id` in a temporary graph, retaining
the source's local placement and frame/joint hierarchy. This lets several final
outputs of one family become separate physical components. Select each physical
part exactly once; exclude prototypes, intermediate outputs and alternate
representations. The command sums full component masses even where they overlap.
It does not subtract overlapping geometry or infer omitted hardware.

Omit a component's `material` to inherit its source assignment. Omit `materials`
to use only existing definitions. A supplied material matching an existing
definition is accepted; conflicting definitions are rejected. A printed part's
effective density must reflect its intended construction if it differs from
a homogeneous solid. Material IDs in the report match those supplied here or in
the input document.

`wing-example.json` selects ten printed parts and two spar solids from the
starter structure generated by `occb-wing-cad --build`. Its densities of
1000 and 1500 kg/m³ are explicitly named assumptions. Replace them with measured
values before interpreting the resulting physical mass. The example's reference
is [`tools/wing-layout/example.json`](../wing-layout/example.json), resolved
relative to the setup file. During verification that example reported 33.793 kg
across 12 selected parts and CG at 33.468% of its 498.533 mm MAC, using those
assumed densities. Its MAC and 897,500 mm² reference area matched the wing
editor's independent planform calculation.

## Chord reference

For `wing_project`, the command reads the supplied layout's span, chord,
leading-edge and height values. Each half-wing uses piecewise-linear station
geometry. For span coordinate y, chord c and leading-edge point LE:

```text
S_half = integral(c dy)
MAC = integral(c² dy) / S_half
LE_MAC = integral(LE c dy) / S_half
S = 2 S_half
CG fraction = dot(CG - LE_MAC, unit chord direction) / MAC
```

Linear-panel integrals are exact for the supplied reference geometry. The MAC
leading-edge point is on the representative positive-span half-wing; its
spanwise coordinate does not affect the X-directed CG fraction. The wing
project uses chord lengths and leading-edge points before twist, with chord
direction +X. It does not derive a new planform from the BREP or compensate for
model parameter edits. Supply a matching layout in the same model coordinates.

For general assemblies, moved wings, or other reference geometry, use
`"kind": "chord"` with a `chord` object in the engine's `ChordReference` format:
`leading_edge` is a length-valued `VectorQuantity`, `direction` a dimensionless
`VectorQuantity`, and `length` a length-valued `Quantity`. Directions need not
be along X or already unit length. All coordinates are world coordinates at
the model's current pose. The CG fraction is signed and may be negative or
exceed one; it is never clamped.

## Report and API

The JSON result includes selected component outputs and materials, physical
properties per component and material, assembly totals, reference geometry,
MAC/planform area when applicable, and CG distance in mm, chord fraction and
percentage. Inertia is the central tensor in world XYZ axes, in kg mm². Each
measurement retains the kernel's relative volume error estimate. Geometry is
generated once per parameter variant and released before return.

Library callers can use `AssemblyMassProperties::material_totals()` and
`balance(ChordReference)` on an existing mass measurement; neither calls the
kernel again. `SymmetricWingPlanform::mean_aerodynamic_chord()` is kernel-free,
unit-aware and O(stations) with O(1) auxiliary storage. It accepts 2–10,000
strictly increasing root-to-tip stations starting at zero; zero tip chord is
supported, while zero-area panels and unrepresentable values are rejected.
No model schema or ABI change is needed.

The scale suite checks 100 integrations of 10,000 stations (5 s budget) and
mass/material/CG reporting for 10,000 components sharing one geometry variant
(10 s budget). Run `tools/bench/run.sh` or `cargo bench --bench balance` with the
native library environment configured.
